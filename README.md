# ตัวช่วยแชร์ Wi‑Fi สำหรับ Android

แอป Flutter นี้ช่วยตรวจสอบการเชื่อมต่อ Wi‑Fi และพาผู้ใช้ไปยังหน้าตั้งค่า Wi‑Fi หรือฮอตสปอตของ Android เพื่อแชร์การเชื่อมต่อด้วยความสามารถที่ผู้ผลิตโทรศัพท์มีให้ เหมาะสำหรับ **Android เครื่องปกติที่ไม่ root** (Android 7.0 / API 24 ขึ้นไป)

> แอปนี้เป็นตัวช่วยตั้งค่า ไม่ใช่ Wi‑Fi repeater ที่ควบคุมฮอตสปอตเอง แอปทั่วไปบน Android ไม่มีสิทธิ์เปิดฮอตสปอต แก้ชื่อ/รหัสผ่าน หรือบังคับให้รับและปล่อย Wi‑Fi พร้อมกันโดยอัตโนมัติ

## ขอบเขตที่รองรับ

- แสดงว่า Wi‑Fi เปิดอยู่และเชื่อมต่ออยู่หรือไม่
- แจ้งเตือนเมื่อ Android ยังยืนยันไม่ได้ว่า Wi‑Fi ต้นทางออกอินเทอร์เน็ตได้
- แสดงชื่อเครือข่าย (SSID) เมื่อ Android อนุญาตให้เข้าถึง
- ขอสิทธิ์ที่จำเป็นสำหรับการอ่านสถานะ Wi‑Fi
- เปิดหน้าตั้งค่า Wi‑Fi ของระบบ
- เปิดหน้าตั้งค่า Wireless/ฮอตสปอตของระบบ
- แสดงความสามารถของอุปกรณ์ในการใช้งาน Wi‑Fi และฮอตสปอตพร้อมกันบน Android 11 ขึ้นไป เมื่อระบบรายงานข้อมูลนี้ได้

## ข้อจำกัดของ Android เครื่องปกติ

- แอปไม่สามารถเปิดหรือปิดฮอตสปอตเองอย่างเงียบ ๆ ได้ ผู้ใช้ต้องยืนยันในหน้าตั้งค่าระบบ
- Android ไม่มี deep link สาธารณะที่รับประกันว่าจะเปิดหน้าฮอตสปอตโดยตรง แอปจึงเปิดหน้า Wireless settings และอาจถอยกลับไปหน้า Settings หลัก ผู้ใช้ต้องเลือกเมนูฮอตสปอตเอง
- การเปิดฮอตสปอตแล้วจะยังคงรับอินเทอร์เน็ตจาก Wi‑Fi เดิมหรือไม่ ขึ้นกับชิป Wi‑Fi, Android, เฟิร์มแวร์ของผู้ผลิต และข้อกำหนดของผู้ให้บริการ เครือข่ายมือถือบางรุ่นอาจถูกเลือกเป็นต้นทางแทน หรือ Wi‑Fi อาจถูกตัด
- ผลว่าอุปกรณ์ “รองรับพร้อมกัน” เป็นข้อมูลจาก `WifiManager.isStaApConcurrencySupported` ไม่ได้รับประกันว่าผู้ผลิตหรือผู้ให้บริการจะเปิดใช้ฟังก์ชันนี้ในทุกสถานการณ์ และ Android 10 หรือต่ำกว่าจะแสดงว่าไม่ทราบ
- สถานะอินเทอร์เน็ตอ้างอิงการตรวจสอบเครือข่ายของ Android แบบ best effort; captive portal, VPN หรือเครือข่ายองค์กรอาจทำให้ผลต่างจากการใช้งานจริง
- ชื่อและตำแหน่งเมนูฮอตสปอตแตกต่างกันใน Samsung, Pixel, Xiaomi, OPPO และผู้ผลิตรายอื่น
- แอปไม่ได้ทำ NAT, VPN, proxy หรือสร้าง `LocalOnlyHotspot` เอง และไม่สามารถทำให้เครื่องที่ฮาร์ดแวร์ไม่รองรับกลายเป็น repeater ได้

## วิธีใช้งานบนโทรศัพท์

1. เชื่อมต่อโทรศัพท์กับ Wi‑Fi ต้นทางตามปกติ
2. เปิดแอปและอนุญาตสิทธิ์ตำแหน่งเมื่อระบบถาม (Android กำหนดสิทธิ์นี้สำหรับการอ่านชื่อ Wi‑Fi)
3. ตรวจสอบว่าการ์ดสถานะแสดงว่าเชื่อมต่อ Wi‑Fi แล้ว
4. แตะ **เปิดการตั้งค่าฮอตสปอต**
5. เลือกเมนูฮอตสปอต เปิดใช้งาน และตั้งชื่อเครือข่ายกับรหัสผ่านใน Android Settings
6. กลับเข้าแอปแล้วกดรีเฟรชเพื่อตรวจสถานะอีกครั้ง
7. ทดลองเชื่อมต่ออุปกรณ์อีกเครื่องและตรวจว่าออกอินเทอร์เน็ตได้จริง

หาก Wi‑Fi ต้นทางหลุดทันทีที่เปิดฮอตสปอต แสดงว่าอุปกรณ์หรือซอฟต์แวร์รุ่นนั้นไม่รองรับการแชร์ Wi‑Fi แบบพร้อมกันผ่านเมนูปกติ แอปไม่สามารถข้ามข้อจำกัดนี้ได้โดยไม่ใช้สิทธิ์ระดับระบบหรือ root

## สิทธิ์ที่ใช้

สิทธิ์จริงที่ Android ขอขึ้นกับเวอร์ชันระบบ:

- `ACCESS_NETWORK_STATE` ใช้ตรวจสอบเครือข่ายที่เชื่อมต่ออยู่
- `ACCESS_WIFI_STATE` ใช้อ่านสถานะการเชื่อมต่อ Wi‑Fi
- `ACCESS_FINE_LOCATION` ใช้อ่านชื่อเครือข่าย (SSID) ตามข้อกำหนดของ Android ทุกเวอร์ชันที่แอปรองรับ

แอปไม่ได้เรียกอ่านพิกัด GPS, ไม่เก็บรหัสผ่าน Wi‑Fi และไม่ส่งข้อมูลเครือข่ายไปยังเซิร์ฟเวอร์ แต่ Android จัด SSID เป็นข้อมูลที่อาจเกี่ยวข้องกับตำแหน่ง จึงแสดงคำขอสิทธิ์ตำแหน่ง การปฏิเสธสิทธิ์ไม่กระทบการเปิดหน้าตั้งค่าหรือสถานะเชื่อมต่อโดยรวม แต่ชื่อ Wi‑Fi จะไม่แสดง บนอุปกรณ์บางรุ่นอาจต้องเปิดบริการตำแหน่งของระบบด้วยจึงจะเห็น SSID

## เตรียมเครื่องพัฒนา

ต้องมี Flutter SDK, Android SDK และโทรศัพท์ Android หรือ emulator ที่ตั้งค่า `adb` แล้ว จากโฟลเดอร์โปรเจกต์ให้รัน:

```sh
flutter doctor
flutter pub get
flutter devices
```

## รันและสร้าง APK

รันบนอุปกรณ์ที่เชื่อมต่อ:

```sh
flutter run
```

สร้าง APK แบบ release:

```sh
flutter build apk --release
```

ไฟล์จะอยู่ที่ `build/app/outputs/flutter-apk/app-release.apk` โปรเจกต์ตัวอย่างยังใช้การเซ็นแบบ debug จึงควรตั้งค่า release signing ของตนเองก่อนเผยแพร่จริง

ก่อนนำขึ้น Play Store ให้เปลี่ยน `applicationId` ตัวอย่าง `com.example.wifi_repeater` ใน `android/app/build.gradle.kts` เป็น package ID ของเจ้าของแอปด้วย

## การทดสอบ

รัน static analysis และ widget tests:

```sh
flutter analyze
flutter test
```

ควรทดสอบบน **โทรศัพท์จริงอย่างน้อยสองยี่ห้อ** เพราะ emulator มักไม่มีฮอตสปอตจริง และหน้าตั้งค่ากับความสามารถรับ/ปล่อย Wi‑Fi พร้อมกันแตกต่างกันตามผู้ผลิต ตรวจอย่างน้อยกรณีต่อไปนี้:

- ยังไม่ให้สิทธิ์, ให้สิทธิ์ และปฏิเสธสิทธิ์
- Wi‑Fi ปิด, เปิดแต่ยังไม่เชื่อมต่อ และเชื่อมต่อสำเร็จ
- เปิดหน้าตั้งค่า Wi‑Fi และ Wireless/ฮอตสปอตได้
- กลับจาก Settings แล้วรีเฟรชสถานะได้
- อุปกรณ์ปลายทางเชื่อมต่อฮอตสปอตและใช้อินเทอร์เน็ตจาก Wi‑Fi ต้นทางได้จริง
